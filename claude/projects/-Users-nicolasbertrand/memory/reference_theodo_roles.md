How roles work at Theodo:
- Roles are organized in **tracks** of expertise; tracks share an area, levels differ.
- Each role has competencies broken down into **savoirs / savoir-faire / savoir-être** — differentiating, not exhaustive, evaluated quarterly + at end of each project.
- Progression is driven by **client need + competency mastery + readiness**, formalized in a **Role Decision Record**.

When assigning R&R in a Theodo SOP or lifecycle standard:
- Use the canonical role names from this DB (do not invent or paraphrase).
- Match the Q7 expectation level implied by the activity to the right role level (e.g. a role responsible for a "key process" sits at Q7=5).
- Cross-reference the standard's R&R rows back to this page so role definitions stay single-source-of-truth.
